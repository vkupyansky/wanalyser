# Разработка

- `main.py`: webhook и периодические проверки; `handlers.py`: пользовательские сценарии.
- `database.py`: PostgreSQL; `api.py`: Warframe Market v2; `utils.py`: каталог, топы и явное создание дампа.
- `config.py`: обязательная конфигурация; `middlewares.py`: регистрация и ограничение запросов; `tests/`: изолированные проверки.
- Сохраняйте существующие данные и поведение. Не создавайте дампы и не запускайте массовые сообщения без прямого поручения.
- Не включайте `.env`, `database_dumps/`, `blocked.txt`, персональные данные и секреты в Git или логи. Реальные credentials не применяются в тестах.
- Административные действия требуют текущей роли; действия с подписками проверяют владельца на серверной стороне.
- SQL использует параметры, финансовые и реферальные изменения выполняются атомарно. Не заменяйте проверку прав скрытой кнопкой.
- Секрет webhook генерируется один раз, `.env` создаётся с правами `0600` и не перезаписывается.
- Зависимости устанавливаются через `uv sync --frozen`; изменения сопровождаются обновлением `uv.lock`.
- Проверка: `uv run --frozen python scripts/check.py`. Предупреждения Python считаются ошибками; исправленные риски покрываются регрессионными тестами.
- Перед публикацией проверьте состав Git и выполните `gitleaks git --redact`. Секретов не должно быть в коде, логах и истории Git.
- При изменении поведения обновляйте [README](README.md) и [STATUS](STATUS.md). Текущее состояние не должно превращаться в историю отладки.
